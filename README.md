# knowledge-test-kit

Turn a folder of JSON questions into a **fully-static knowledge test site**
with local practice, review-status filtering, and Pagefind search. Domain-
agnostic — bring your own knowledge bank.

> Status: `v0.1.0` — scaffold + demo bank + reusable Pages workflow. See
> [`STATUS.md`](./STATUS.md) and [`DECISIONS.md`](./DECISIONS.md) for what is
> and isn't done in this release.

---

## Quick start

Clone and run against the built-in demo bank:

```bash
git clone https://github.com/clt123321/knowledge-test-kit.git
cd knowledge-test-kit
npm install
npm run dev
```

The dev server prints a URL (default `http://localhost:4321/`). It also
shows how many questions, modules, and review statuses were detected.

## Point it at any other knowledge bank

Zero-config: `knowledge-test-kit` auto-detects three content layouts.

```bash
# Sibling RL question bank (legacy `src/data/questions/` layout)
npm run dev -- --content ../rl-question-base

# ML compiler bank
npm run dev -- --content ../ml-compiler-knowledge-test

# A canonical `questions/` layout
npm run dev -- --content ./examples/demo-bank
```

## Validate a bank before publishing

```bash
npm run validate -- --content ../rl-question-base
```

You get a report with:

- unparseable JSON files
- duplicate question ids
- missing `explanation` / `optionExplanations`
- module ids that don't resolve
- illegal answer sets for single-choice items
- review-status distribution + auto-remaps

## Build the static site

```bash
npm run build -- --content ../rl-question-base
```

Produces `dist/` (Astro output + Pagefind index). Deploy `dist/` anywhere
that serves static files.

## Create a new knowledge bank

Until the npm package is published (see `DECISIONS.md` §9), use the
in-repo alias:

```bash
# planned once published:
#   npx knowledge-test init my-bank

# today, inside this repo:
npm run cli -- init my-bank
```

This scaffolds a **lightweight** content-only repo:

```
my-bank/
├── questions/
├── references/
├── syllabus/
├── reviews/
├── knowledge-test.config.json
├── README.md
└── .github/workflows/pages.yml
```

Your bank does **not** copy the Astro app; it only owns content.

## Deploy to GitHub Pages

In the content repo:

1. Repository **Settings → Pages → Source → GitHub Actions**.
2. Commit and push.
3. `.github/workflows/pages.yml` (generated by `knowledge-test init` or
   `knowledge-test deploy-init`) uses the reusable workflow at
   `clt123321/knowledge-test-kit/.github/workflows/deploy-content-site.yml@v0.1.0`.

If reusable-workflow deploys hit permission issues on your account, fall
back to the inline template in
[`docs/DEPLOYMENT.md`](./docs/DEPLOYMENT.md).

## Local practice mode — data stays in your browser

- No accounts.
- No backend, no database.
- Answers, wrong-question queues, and confidence scores live only in
  `localStorage`, namespaced by bank id.
- Export a JSON snapshot from the Practice page; import it later.
- Clear site data → all records gone.

```
apps/site/                Astro static site (renderer)

                          SKILL.md + prompt templates for content authoring
docs/                     Deployment, integration plans, known limitations
```

agent should follow inside this repo.
